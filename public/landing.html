// How it works

  1. 01

    Encrypt

    The file is encrypted in your browser with a random key. The server only ever stores ciphertext.

  2. 02

    Split

    The key is split into N Shamir parts, K needed. Each holder's part is also wrapped, so holders cannot pool parts early.

  3. 03

    Lock on NEAR

    The contract stores the file hash, holders and unlock time. Every early release or open is refused and written to a public log.

  4. 04

    Release

    At the second, K holders release on-chain. Viewers' browsers rebuild the key, check the hash and open the file.

// What NEAR enforces

  • No release or open before the unlock time
  • Only listed holders can release, each once, with the committed part
  • K parts required in split mode
  • Every attempt, accepted or refused, in a public log
  • Alert hashes anchored; locations stay off-chain

// Honest limits

  • The release service plus K holders together could open early; neither alone can
  • Single mode trusts the release service with the key until the time
  • The person who seals already has the original file
  • Nothing stops a photo after the file opens
  • IP location is approximate; GPS only with consent
